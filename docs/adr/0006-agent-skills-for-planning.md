# 0006 · 排查方法写成 Agent Skills，只在生成计划时按需加载

## 状态

已采纳

## 背景

调查 Agent 生成计划时，依据是提示词与检索到的运维手册。运维手册写的是 Kubernetes 的背景知识与处置，用的是 `kubectl` 的说法；扁鹊自己怎么查一类故障（用哪个证据域的哪个工具、期望什么证据、什么证据对应哪个根因类别、什么时候需要变更证据）没有成文的地方，只能写进所有告警共用的计划提示词。

[Agent Skills](https://agentskills.io/specification) 格式把这类说明写成带名称与用途的 `SKILL.md`，并约定渐进加载：模型先只看目录，选中后才加载正文。项目级 skill 的跨客户端约定位置是 `.agents/skills/`，Claude Code 读的是 `.claude/skills/`。

需要决定的是：skill 放在哪里、在调查的哪些环节加载、与运维手册检索是什么关系、加载 skill 的函数是否进入工具注册表，以及 skill 能否当作证据或参考资料。

## 决定

1. 每类故障的排查方法写成一个 skill，放在仓库根目录的 `.agents/skills/<name>/SKILL.md`；`.claude/skills` 是指向 `../.agents/skills` 的相对符号链接，只维护一份文件。正文里的工具名就是注册表与 MCP 的工具名，接上扁鹊 MCP 的外部客户端可以按同一份 skill 调用工具。
2. 后端启动时按格式严格校验全部 skill（名称、描述、字段、正文长度、没有脚本与可执行文件），不合规即启动失败。扁鹊只加载自己仓库里的 skill，不采用格式为兼容其他来源建议的宽松加载。
3. 只在生成计划与补充计划时加载。系统提示词只放目录（名称与用途，按名称排序）；请求同时提供 `activate_skill` 与 `submit_plan`，模型必须调用其一，`activate_skill` 的名称参数是目录名称的枚举。同一次调查已加载的 skill 再激活只返回「已加载」；每次计划生成的激活次数有上限（`BIANQUE_PLAN_MAX_SKILL_ACTIVATIONS`，默认 3），到上限后只提供 `submit_plan`。补充计划的提示词带着已加载 skill 的正文。取证子 Agent、判断、报告与追问不加载 skill，skill 的指导经由计划步骤的建议工具与期望证据传下去。
4. 与运维手册检索并存：计划阶段照旧注入检索到的手册。skill 写扁鹊怎么查，手册写背景与处置并可列为参考资料；skill 需要背景时写手册的主题名，不复述手册，手册不写扁鹊的工具名。
5. `activate_skill` 不进工具注册表，也不经 MCP 提供。注册表里的工具是取证工具与给 MCP 客户端的辅助工具，都经工具执行器；激活不取证，结果不是证据，放进注册表会让它出现在取证子 Agent 与 MCP 的工具列表里。
6. skill 不是证据，也不是知识：证据门的 `knowledge_boundary` 拒绝出现在任一引用字段、报告与回答的 `references`、计划的 `knowledge_refs` 里的 skill 名称；正文里提到 skill 名称不算违规。
7. skill 进入可复现的范围：目录在系统提示词里、正文在函数结果里，都进请求键；录制清单记录每个 `SKILL.md` 的 SHA-256，`recorded` 模式启动时与文件比对，不一致即失败并指出文件。每次激活写一条 `kind=skill` 的调用记录，每版计划记录生成时已加载的 skill，评测报告逐用例列出加载过的 skill。

## 后果

正面：

- 排查方法从共用的计划提示词里拆出来，按告警按需加载；换一个领域时改 skill，不改调查图与提示词结构。
- 扁鹊与外部客户端共用同一份 skill，外部客户端经 MCP 调用的是同一组工具。
- 加载了哪些 skill 写进调用记录与计划版本，显示在调查详情页上，评测报告逐用例列出，读者能看出 skill 对计划的影响。

负面：

- 计划节点从一次强制调用变成短循环，每次计划生成多出 0 至 3 次模型调用，token 随之增加；调查的 token 预算没有为此调整。
- 改 skill 与改提示词一样会改变请求键，需要用真实模型重新录制全部用例。
- 与只有知识检索时的对比只基于各一次真实运行，不能说明模型每次的表现（[ADR 0005](0005-recorded-model-responses-for-eval.md)）。
- 模型可能不加载任何 skill，或加载与告警不相符的 skill；评测报告如实记录每个用例的加载情况。
- skill 与运维手册的内容可能逐渐重叠，审阅 skill 改动时要按第 4 条的分工检查。
- 在没有开启符号链接支持的 Windows 克隆里，`.claude/skills` 是一个内容为路径的文本文件，Claude Code 读不到 skill。
